# Fase 7 — LGPD Bloco 1 (Legal/Consentimento) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a privacy policy + terms of use, and require explicit consent (checkbox) on the only public self-registration flow of the system.

**Architecture:** Additive Prisma field (`User.termsAcceptedAt`) + server-side validation on `POST /auth/register` in the api; two new public i18n-driven pages (`/privacidade`, `/termos`) plus a required checkbox wired into the existing register form in the front. Mobile is untouched (no self-registration screen there).

**Tech Stack:** Bun + Elysia + Prisma (api); Vite + React 18 + TypeScript + react-router-dom + i18next/react-i18next + shadcn/Radix UI (front).

**Spec:** `C:/RN/TozzoBurger/docs/superpowers/specs/2026-08-29-fase-7-lgpd-legal-consent-design.md`

## Global Constraints

- Migration must be additive/nullable, no destructive operation, tested in an ephemeral Postgres before being treated as validated (project-wide convention, see `plano.md`).
- No retroactive re-consent for existing users — `termsAcceptedAt` stays `null` for them, nothing else reads/enforces it.
- Legal page text is a draft, explicitly marked as pending real legal review — this is not legal advice.
- All new user-facing text (both the 2 legal pages and the new checkbox label) must exist in exactly the 6 supported locales (`en`, `pt-BR`, `es`, `fr`, `zh`, `hi`) and pass `bun run scripts/check-i18n.mjs` (no missing/extra key, no placeholder mismatch, no literal `TODO`/`TBD`/etc.).
- Mobile (`TozzoBurger` repo) is out of scope for every task in this plan — it has no registration screen.
- `MANAGER`/`EMPLOYEE` accounts (created via `modules/users/`, not via `/auth/register`) are out of scope — they never see this consent flow.
- Never push, open a PR, or merge to `dev`/`main` from inside a task — this plan produces local commits only, integration is a separate controller decision.
