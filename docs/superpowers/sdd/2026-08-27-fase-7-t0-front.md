## 3. Payload de sync mobile no front

Não existe implementação de push/pull do sync mobile no front atual. Busca real em src:

~~~text
rtk grep -vvv -l 400 -m 1000 -n "sincronizacao|/sync|synchronize|getChanges|pushChanges|pullChanges" src
1 match in 1 file:
src/i18n/locales/en.json:543:"lastSynced": "Last synchronized"
~~~

Não foram encontrados /sincronizacao, getChanges, pushChanges, pullChanges ou chamadas de sincronização em código do dashboard. Consequentemente:

- o front não monta o payload de push do mobile;
- o front não consome o envelope de pull do mobile;
- não há campos de produtos, pedidos, vendas ou itens de sync a inventariar neste repositório;
- a camada src/lib/legacyWire.ts é uma conversão genérica do wire usado pelos serviços HTTP do front, mas o fluxo de sincronização mobile é implementado em TozzoBurger/services/api.ts e TozzoBurger/database/useSyncDatabase.ts.

Os endpoints de pedidos usados pelo front são operações do dashboard, não o sync mobile: src/components/dashboard/PedidosTab.tsx:297 e :305-308 fazem POST de status, e src/layouts/DashboardLayout.tsx:168 faz GET com filtro NOT_CLOSED.
